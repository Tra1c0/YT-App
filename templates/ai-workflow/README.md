# AI workflow template: a working memory that checks itself

A small set of files that gives AI coding sessions a reliable, cheap
memory of a project: every session starts with the current state, reads only the part of the code
map it needs, and a check fails when the docs fall behind the code. Stdlib Python 3.8+, no
packages, any language or framework.

## What is in it

| File | Purpose |
| --- | --- |
| `CLAUDE.md` | The instruction set every session loads: read order, terms, do / don't, which doc to update when. Each rule stated once. |
| `docs/HANDOFF.md` | Short memory for the lead: current state, open points, how to work, dead ends, repeated mistakes, build log. |
| `docs/ARCHITECTURE.md` | Code map by area, with generated contents and file inventory; numbered pitfalls. |
| `docs/FEATURES.md` | What exists, for the owner, with honest status letters (E / T / –). |
| `docs/ROADMAP.md` | What is not built: Decided / Maybe later / Unsorted. Sessions build only from "Decided". |
| `release-notes/next.md` | User-facing notes of the next push (CI can put them into the release). |
| `scripts/docs_sync.py` | The generator and checker (one file, stdlib only). |
| `scripts/docs_sync.json` | Its config: the only project-specific part. |
| `scripts/install-hooks.sh` | Optional git pre-commit hook that runs the check. |
| `.claude/settings.json` + `.claude/hooks/session-start.sh` | SessionStart hook: prints state, map index and check summary (≤ 15 lines). |
| `.github/workflows/docs-check.yml` | CI job (or copy its one step into your build workflow). |

## Why it saves tokens and prevents drift

- **No exploring from scratch.** The code map names every source file (enforced), so a session
  finds the right files from one section instead of searching the tree.
- **Read one section, not the file.** The session-start output lists each map section's start
  line; the session reads that range only. Areas, not rounds: facts never scatter over
  "notes of round N" sections.
- **State without reading.** The SessionStart hook prints the "Current state" block and the open
  gaps of the docs check before the first prompt.
- **Generated, not remembered.** Lists that can be derived (contents, file inventory, enum values
  and counts) are regenerated by `--write`; a stale block fails the check.
- **One place per fact.** CLAUDE.md holds rules, HANDOFF.md process and state, ARCHITECTURE.md code
  facts and pitfalls, FEATURES/ROADMAP the owner's view. No rule is repeated, so none can
  contradict another.
- **Short sessions.** A new session per round, started by the hook, costs a few hundred tokens of
  context instead of a summarised marathon.

## Adopt it in 10 minutes

1. Copy the contents of this folder into the repository root (keep `.claude/` and `.github/`;
   merge into an existing `.claude/settings.json` by adding the `SessionStart` hook).
2. Edit three values in `scripts/docs_sync.json` (marked EDIT):
   `map.sources` (globs of the files the map must name, e.g. `src/**/*.ts`), `base_branch`, and
   `warn_if_changed[0].when` (the code that ships). Optional: `aliases`, `lists` + `counts` (e.g.
   an enum whose size a doc states), `commands` (other fast checks), `copies` (files that must stay
   identical).
3. Fill the placeholders `<…>` in `CLAUDE.md` and `docs/*.md`.
4. Run `python3 -I scripts/docs_sync.py --write`, then `--check`: add every file it lists to its
   area in `docs/ARCHITECTURE.md` (by name, stem or a backticked glob like `user_*.py`) until it
   is green.
5. Optional: `bash scripts/install-hooks.sh` (pre-commit: blocks commits on the base branch only;
   on other branches it prints the problems). Remove with `--remove`.
6. CI: keep `.github/workflows/docs-check.yml`, or add its step to your build before compiling.

## How the check works

`python3 -I scripts/docs_sync.py --check` (exit 1 on errors):

- Errors: a `<!-- gen:NAME -->…<!-- /gen:NAME -->` block differs from what `--write` would
  produce; a source file is not named in the map outside generated blocks (file name, stem when
  `match_stem` is on, or a backticked glob; `**`, `*`, `?`, `{a,b}` work, aliases expand); a
  configured count does not match its list; a configured command fails; a configured copy differs.
- Warnings: `warn_if_changed` rules (e.g. code changed but the release notes are empty, or a
  vendored file changed without its change log); names or globs in the map that point at nothing;
  `size_warnings` (a file grew past a size worth a look). Warnings never fail.
- The diff for the warnings: staged changes with `--staged`; else everything since the merge base
  with `base_branch` plus uncommitted changes; else the last commit; `--base REF` overrides.

Other modes: `--write` (regenerate blocks and copies, then check), `--brief` (session start, never
fails), `--toc FILE` (section line ranges of any markdown file), `--no-commands` (skip external
commands, e.g. when CI runs them as own steps). Generated block types: `toc` (from each `## `
heading and its `> ` line), `inventory` (source files grouped by folder, collapsed), `list` (items
of a `lists` entry through a template with `{count}` and `{items}`).

## Keeping it alive

- Lead, every push: update the docs per the table in `CLAUDE.md`, run `--check`.
- End of a round: update HANDOFF.md, delete what is no longer true. Do not cut useful facts to
  reach a line count; move code facts to their ARCHITECTURE.md area instead.
- To share the script between repositories without drift, keep one copy as the source and list
  the others under `copies`.
